# Local audit retention

The managed runtime keeps supplementary JSONL audit records at `<ledger>.events.jsonl`. This is an operational log, not the authoritative WAL, a user balance, or a supplier invoice. Budget protection settings do not disable auditing. Do not apply external `copytruncate`, delete the active file, or rotate the WAL with this policy.

`AuditOptions` defaults to 16 MiB per active file, eight archives, and seven days of archive retention. Zero values select defaults; negative values are rejected. The active journal rolls before a queued batch would exceed its size target. A batch contains at most 64 records of at most 16 KiB each. Records and batches are never split across files. Thus each newly managed file is bounded by `max(MaxBytes, 1 MiB)`, and the default managed audit footprint is at most 144 MiB, excluding filesystem metadata and an inherited oversized file from earlier releases. The latter is preserved on first rotation and ages out normally. These limits apply only to the exact managed filename namespace, not other files in the directory.

Retention runs at open, before rotation, and every minute even without traffic. An active nonempty file is also rotated after `MaxAge` (the first record time in the current process, or active file modification time after restart). Archive age is measured from rotation, so it is not a strict event-level seven-day deletion guarantee. Disk count/size limits may evict archives earlier. Collect logs before eviction if longer history is required.

Archives are named `<ledger>.events.jsonl.archive-<UTC nanosecond timestamp>-<32 hex random characters>.jsonl`. Each archive publication uses a hard link that refuses to overwrite an existing path, then removes the active name and creates a fresh active file exclusively. This requires a filesystem supporting same-directory hard links (local Linux filesystems and NTFS). The ledger ownership lock must remain held for the journal's entire lifetime. Store the directory privately; concurrent external mutation is unsupported. Active paths and recognized archive paths must be regular files; symlinks/directories are rejected. Other filenames are ignored and never cleaned up.

Every acknowledged batch has completed file `Sync`. Rotation syncs existing data first and, on Unix, syncs directory changes. Windows preserves file-sync semantics but does not support directory sync through Go's `os.File.Sync`. A crash between link creation and active-name removal can leave two names for the same inode; restart removes only the duplicate archive name before accepting writes. A crash after active-name removal leaves the complete archive and restart creates a fresh active file. The existing incomplete-tail repair and rejection of damaged complete active records remain in effect. Archived files are immutable and are not scanned to reconstruct runtime state.

Write, sync, rotation, or retention errors poison the journal and subsequent appends return the error; requests retain the existing audit-failure handling. Closing drains submitted records. This intentionally prevents an apparently successful audit append after storage failure.

For log collectors, watch both the active filename and the exact archive pattern, track file identity/inode and offsets across name changes, and avoid ingesting the transient second hard-link name as a second file. Ship to the existing log platform before local retention expires; archive storage there is a separate policy. Never assume path-only tracking provides exactly-once ingestion. No collector endpoint, remote upload, or centralized retention is configured by this implementation.
