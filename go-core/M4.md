# M4：管理衔接、对照测试与回滚准备

当前交付为本地候选验证，生产未部署、流量未切换。管理页面和账本往返已经实测；正式 M4 容量出口仍需共同资源配额、业务分布及 SLO，不能仅凭本地探索结果进入生产切换。

## 管理台连接

Node 管理服务与 Go 适配器必须读取同一份明确指定的 `CONFIG_PATH`。Node 保留现有草稿、影响预估和发布检查，Go 只在管理员显式加载时发布新配置代际。

在受保护的本地运行配置中设置以下变量，不把真实值写入仓库或终端记录：

| 变量 | 用途 |
|---|---|
| `ADMIN_TOKEN` | Node 管理台原有登录凭据；启用桥接时必须存在 |
| `AMR_GO_ADMIN_URL` | 固定的 `http://127.0.0.1:端口`，禁止域名、路径、重定向及非本机地址 |
| `AMR_GO_ADMIN_TOKEN` | Go auth 配置中的独立 `adminToken`，至少 16 字符，仅留在 Node 服务端 |
| `CONFIG_PATH` | 与 Go Node 适配器 `--config` 相同的配置文件 |

未设置 `AMR_GO_ADMIN_URL` 时默认关闭，接口返回 404，管理面板隐藏。启用后，总览新增“实验 Go 核心”：显示保存版本和实际生效版本；“将已保存配置加载到 Go”只加载已保存文件，不上传浏览器草稿，不修改入口流量。其余管理台业务指标仍来自 Node，不代表 Go 运行指标。

| 管理接口 | 行为 |
|---|---|
| `GET /admin/api/go-core` | 返回 Go runtime revision、Go config revision、Node saved revision，以及 `synchronized` |
| `POST /admin/api/go-core/reload` | 需要上一条查询的 `If-Match`；缺失 428，冲突 409，Go 拒绝新配置 422 |

两条接口沿用现有管理员 Bearer/HttpOnly cookie 与同源检查，Go 凭据不发给浏览器。桥接只访问固定路径，不转发任意 URL、Cookie 或上游错误正文。响应大小限制 64 KiB，总等待上限 5 秒。超时是**结果未知**，面板会重新查询，不自动重试更新。

“配置保存”和“Go 加载”是两个明确步骤，并非跨进程事务。保存后页面会显示尚未同步；加载非法配置时，Go 继续使用上一代。查询中的两侧版本仅是查询时的快照，其他管理员之后可能再次保存；新一轮操作仍依赖 Go CAS。Go 管理员凭据若同时轮换，应同步修改 Node 服务端桥接凭据并重启管理服务。

## 可复现验证

```powershell
./go-core/verify.ps1
node --test tests/go-core-admin.test.mjs
node go-core/compat/demo-rollback.mjs --binary data/go-migration/amr-core.exe
node go-core/compat/compare-gateways.mjs --binary data/go-migration/amr-core.exe --seconds 5 --rounds 3 --concurrency 1,8,32 --out data/go-migration/gateway-comparison.json
node go-core/compat/summarize-gateways.mjs data/go-migration/gateway-comparison.json data/go-migration/gateway-comparison.md
```

Linux 使用对应构建出的无 `.exe` 二进制。Windows 资源采样用原生 `Get-Process`，Linux 用 `/proc` 与 `getconf CLK_TCK`。可加 `--chunk-ms` 调整 SSE 段间等待（40–1500 ms），加 `--ui-python` 指定已安装 Playwright 的 Python，执行真实浏览器登录、不同步展示和加载操作。不会自动安装依赖。CI 运行小规模 smoke、账本往返及 Go race 检查，不用 CI smoke 数值宣称容量。

所有测试使用临时目录、随机凭据、本机模拟上游。比较脚本不继承生产 endpoint/key、不加载 `.env`。失败观察会保存在 `.failure.json`，不会把失败请求排除后只报成功延迟。每次正式记录使用新的 `--out` 路径，避免覆盖证据。

完整对照结果见 [M4 实测表](../docs/go-core-m4-results.md)。原始证据位于 `data/go-migration/gateway-comparison-20260909.json`：54 组、52,059 次测量请求和 15 次预热。此轮每组发起窗口 5 秒，3 次轮换顺序，SSE 段间 200 ms。本机 Docker 引擎不可用，未实施共同强制配额，因此只认定探索性验证。

完整性能对照所用二进制早于新增 `ledger-export`，其 SHA256 已写入原始记录；其后 Go 变化为新增离线导出命令及分派，网关代码未变。最终候选另行通过 smoke、85 项 Go 测试、5150 条差分和账本往返；不会将早期二进制哈希冒写为最终候选哈希。Node 全套 409 项测试中，406 项首次通过，3 项浏览器用例因沙箱 `spawn EPERM` 失败后在允许启动 Chromium 的环境重跑通过；新增面板也完成真实浏览器和桌面/手机截图检查。

## 灰度前必须冻结的条件

1. 明确入口、唯一流量范围（建议独立测试租户或完整预算域）、测试时段、开关与退出条件。Go 当前仍强制 loopback，尚不是可直接替换公网入口的部署包。
2. 确定目标 RPS、同时在线 SSE 数、请求大小/工具/图片/长历史分布，及允许的错误率、完整交付率、网关附加 P95/P99 延迟。增加开放负载与长连接测试；不能用两个交错 P95 相减当作附加 P95。
3. 为 Node 服务与 **Go + 适配器整体** 设置相同 CPU/内存配额；统一上游配额、模型、策略与计费口径，再在目标环境重复测试。
4. 明确唯一账本写入方。不能让 Node/Go 同时为同一个日预算域分别放行，也不能镜像真实生成请求；双写日志不能成为双调用模型。
5. 备份入口配置、Node 配置和账本、Go WAL/审计、镜像与提交；演练关闭入口、排空、账本迁移和恢复入口。对真实业务质量与人工复核另作验收，不把选模 parity 当作回答质量证据。

## 已验证的离线账本往返

`ledger-import` 已能将冻结的 Node 账本导入新的 Go WAL。新增 `ledger-export` 将冻结的 Go WAL 生成新的 Node JSON，用于回滚时保留 Go 期间的实际/估算金额。

```powershell
# 前置：入口已关闭；Node 与 Go 写入方都已停止，未完成请求已结算。
# 下列文件名为演练示例；实际必须使用本次冻结并留存的文件。
$frozenWal = 'data/cutover/go-frozen.wal'
$newNodeLedger = 'data/cutover/node-rollback-new.json'
$walDigest = (Get-FileHash -Algorithm SHA256 -LiteralPath $frozenWal).Hash.ToLowerInvariant()
./data/go-migration/amr-core.exe ledger-export --source-frozen --source $frozenWal --target $newNodeLedger --source-sha256 $walDigest --time-zone Asia/Shanghai
if ($LASTEXITCODE -ne 0) { throw '账本导出失败，保持入口关闭' }
Get-FileHash -Algorithm SHA256 -LiteralPath $newNodeLedger
```

导出命令要求目标不存在，用临时副本验证 WAL 校验链，源文件不改写；校验源哈希并在导出前再次检查。若存在未结算预占、未定价记录、损坏/截断尾部，拒绝导出，须先恢复或对账。当前离线工具限制源 WAL 为 256 MiB，超过限制不能直接回滚，应先准备经验证的大账本迁移路径。`--source-frozen` 是操作者对停写事实的确认，不能代替实际停止进程。

新 Node JSON 保留当日实际/估算金额，预占为 0；历史费用在 Node 中显示为 `legacyUnattributedCostYuan`，细分来源仍保留在 Go WAL，不能声称分类费用、计数、健康和会话全部无损恢复。Node 请求计数从 0 开始。业务时区必须与运行配置一致，并核对导出日期；跨日不能盲用旧日快照。

准备好新 JSON 后，在入口仍关闭时让 Node 配置的 `budget.ledgerPath` 指向该文件，恢复旧 Node 服务并核对账本金额、配置、鉴权和健康。确认没有 Go 写入方后再恢复选定流量。原始 WAL、审计和旧 Node 账本保留，不覆盖、不把两份全量账本相加。Go 已产生新费用后仅恢复原 Node 备份，会漏计 Go 期间费用，禁止这样操作。

`demo-rollback.mjs` 已验证 Node → Go → Node → Go 往返、原文件不变、微元精度、Node 重新加载后新增费用继续保留。此为本地账务演练；尚未执行生产入口切换和实际回滚。
