# 路由设计说明（部署团队必读）

> 回答最常见的三个问题：auto 会把请求发给谁？分流是怎么工作的？什么条件切换语义复核生效？

## 1. auto 会选谁？——三维评分的数学结果，不是配置偏向

评分公式（每个候选模型算一遍，取最高分）：

```
score = 1.0 × quality      ← 该任务类型的实测质量分
      − 0.22 × costIndex   ← 用户侧成本（豆价，越大越贵）
      − 0.10 × costIndexProvider ← 算力消耗指数（自建算力资源消耗，卡/吞吐）
      − 0.14 × latencyIndex ← 相对时延（越大越慢）
      − uncertainty        ← 未验证模型惩罚
      + selfBonus          ← 自建模型加分
      − livePenalty        ← 实时健康惩罚（错误/慢）
```

（权重在管理端「业务策略 → 细调参数」可调；上面是均衡风格默认值。）

**成本双指标**：costIndex 按「算力豆结算价」（用户视角，每豆换多少 token）计算；costIndexProvider 按「部署资源强度」（平台视角，设备×卡×卡价÷单实例吞吐）计算，两者独立配置权重。两个成本会背离——例如某模型豆价便宜但吃卡多（大参数低吞吐），用户省豆的同时平台在贴算力；独立权重让路由同时照顾两侧。

**选型随实测数据走，不固定某个模型。** 2026-08-20 算力豆价调表前，deepseekv4-flash 三维全占优（质量顶格+最便宜+最快），是多数任务的默认选择；调表后 dsf 豆价变为三模型最贵，当前权重下多数任务的最高分转移到 qwen36-35b（质量接近、用户成本与算力消耗显著更低）。以均衡风格默认权重在 12 类代表任务上的模拟为例：结构化抽取/代码/复杂推理/创意类选 qwen36-35b（8 类），事实问答/摘要/工具调用选 deepseekv4-flash（4 类）——**这正是路由器按设计工作的表现：价格或质量实测一变，选型自动跟着变，不需要改代码。**

管理端「业务策略 → 调整影响预估」可在发布前实时复测任意权重组合的逐任务选型；「不做 auto 会怎样」对比表（v0.5.0）给出固定单一模型与当前策略的质量/成本差。

## 2. 分流什么时候发生？

分流不靠硬指定，靠**容差分流（taskPreferences）**：某模型与最优模型的分差 ≤ 容差时，选该模型。逻辑：

- 该模型在这类任务上质量分本就接近最优；
- 分流后质量无实质损失，但可利用该模型的并发余量；
- 一旦预算压力上升（成本权重最高放大 3 倍），分差拉大超容差，**自动回落最优模型**——预算保护语义天然成立。

当前配置（config/router.json `routing.taskPreferences`，质量分为 eval gate 实测口径）：

| 任务 | 分流到 | 容差 | 依据 |
|---|---|---|---|
| extraction（结构化提取） | qwen36-35b | 0.05 | qwen 质量分 0.93 全场最高，用户/平台双成本也最低 |
| creative（内容创作） | qwen36-35b | 0.05 | 质量并列第一梯队，成本显著更低 |
| simple（轻量任务） | qwen36-35b | 0.05 | 质量满足底线，成本最优 |

注意：容差分流只在「质量不打折的区间」生效；任务质量格局变化后，调分数或调容差即可改变分流范围，无需改代码。每次容差分流生效时，决策日志 `preference` 字段记录 `{task, model, note}`（含实际分差与容差），可审计每一条分流决策。

## 3. 语义复核 shadow → active 切换条件（量化）

shadow 模式只记录小模型与规则层的分歧，不改变路由。切换 active 的门槛：

- 复核成功样本 ≥ **500 条**
- 分歧率 ≤ **5%**（分歧 = 小模型与规则层任务类型判断不一致）
- 错误率 ≤ **1%**（分类器服务故障/超时占比）
- 观察期 ≥ **7 天**（覆盖工作日/周末流量模式）
- **决策前先量化**：组件体检面板「切换影响预估」一键在 heldout 标准集上回放三种决策链（规则主导 / 分级采纳 / 全量采纳），输出判准率/质量/成本/误判方向（漏难/多难/同档错）——量化论据齐全再切换

切换方式：管理面板「质量复核」→ 复核结果怎么用 → 正式采用，或 `config/router.json` → `semanticRouter.mode: "active"`。**保守做法（v0.6.0 起用两个明确命名的阈值，minConfidence 保留为兼容别名）**：先设置 `semanticRouter.finalAdoptionThreshold=0.5`（复核最终结果置信度低于 0.5 退回规则层），一周无事故后逐步降 0 全量采纳。级联方式下 `smallAcceptThreshold=0.7` 是第一级升级线：小模型置信度低于它升级大模型复核（prompt 会携带小模型初判作参照）；大模型失败时降级返回小模型结果（small-degraded），两级都失败才退回规则层。回滚：改回 `shadow` 并 reload，即时生效（无需重启）。

切换后出问题时：决策日志（data/decisions/）记录了每次路由的 `semanticReview` 字段，可精确复盘哪些请求受复核影响。

| 面板卡片 | 数据来源 |
