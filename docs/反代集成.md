# 反向代理与 TLS 终结

直连 `0.0.0.0:8787` 在内网/公网都不推荐：没有 TLS、没有访问控制、无法跨实例负载均衡。
本服务内置的鉴权（ROUTER_ACCESS_KEY/ADMIN_TOKEN/METRICS_TOKEN）只适合「IP 白名单 + TLS 终结在反代」的环境。

## 1. Nginx（推荐）

### 1.1 HTTP/HTTPS + TLS 终结（最常见）

`/etc/nginx/sites-available/auto-router.conf`:

```nginx
upstream auto_router {
    # 多实例扩容：多个 Node 进程共享同一份 config/router.json（推荐只读 NFS/共享卷）
    server 127.0.0.1:8787 max_fails=3 fail_timeout=10s;
    # server 127.0.0.1:8789 max_fails=3 fail_timeout=10s;  # 第二实例（勿用 8788：已被语义分类器占用）
    keepalive 32;
}

server {
    listen 443 ssl http2;
    server_name router.your-domain.cn;

    ssl_certificate     /etc/letsencrypt/live/router.your-domain.cn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/router.your-domain.cn/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    # 流式响应（SSE/chat completions）必须禁用缓冲并放宽代理超时
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_read_timeout 600s;       # 长流式
    proxy_send_timeout 600s;
    proxy_connect_timeout 5s;
    proxy_http_version 1.1;
    proxy_set_header Connection "";

    # 信任客户端真实 IP（Node 端 /metrics/auth 决策可读 X-Forwarded-For）
    # 仅在反代同机可信的前提下开启
    real_ip_header X-Forwarded-For;
    set_real_ip_from 10.0.0.0/8;
    set_real_ip_from 127.0.0.1;

    location / {
        proxy_pass http://auto_router;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 拒绝公网访问 /metrics（仅内网或经 Prometheus 反代拉取）
    location /metrics {
        allow 10.0.0.0/8;
        allow 127.0.0.1;
        deny all;
        proxy_pass http://auto_router;
    }
}
```

启用：
```bash
sudo ln -s /etc/nginx/sites-available/auto-router.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### 1.2 纯内网 HTTP（运维/测试）

跳过 TLS，直接绑 0.0.0.0:80，加白名单 IP。

## 2. Caddy（自动 HTTPS）

`/etc/caddy/Caddyfile`:
```caddyfile
router.your-domain.cn {
    reverse_proxy 127.0.0.1:8787 {
        flush_interval -1
        transport http {
            dial_timeout 5s
            response_header_timeout 600s
        }
    }
}
```

## 3. HAProxy（负载均衡）

`/etc/haproxy/haproxy.cfg`:
```
frontend router_front
    bind *:443 ssl crt /etc/haproxy/router.pem
    default_backend router_nodes

backend router_nodes
    balance roundrobin
    option httpchk GET /health
    http-check expect status 200
    server node1 127.0.0.1:8787 check inter 5s
    server node2 127.0.0.1:8789 check inter 5s
    timeout tunnel 600s      # SSE 流式需要长隧道
    timeout server 600s
```

## 4. 客户端使用反代后的注意事项

- **HEADER `Authorization` 原样转发**：客户端 `Bearer <token>` 不会被反代改写，但如果用 Nginx 子请求替换鉴权，请确保 token 透传
- **流式响应在 Nginx 下需要 `proxy_buffering off`**：否则 SSE chunk 会等到填满 buffer 才下发，用户看到明显延迟
- **长流式（>10 分钟）：Nginx 默认 `proxy_read_timeout 60s` 必须调到 600s+**，否则中途断流
- **CORS**：当前 Node 端 `Access-Control-Allow-Origin: *` 全开。如在反代上做了 CORS，去掉 Node 端这一行（避免双 CORS 头冲突）
- **`X-Forwarded-For`**：Node 端目前没读取，但日志/限流/反欺诈模块未来会需要——上面示例已透传

## 5. 多实例共享 config

容器化部署时建议把 `config/router.json` 挂载为只读卷：
```yaml
volumes:
  - ./config:/app/config:ro
  - ./data:/app/data   # decision log + budget ledger 可写
```
NFS 共享卷会让更新延迟到 1~10 秒，且无原子写保证。如果配置变更频繁，改用 `etcd`/`consul` + `admin/api/reload`（当前为单进程 reload，多实例需外加广播层）。
