# 反向代理与 TLS

反向代理应连接 Go 公共入口 `8787`。`8789` 是 Node 内部管理与结果接口，`8791` 是 Go 内部接口，都不能作为第二个业务后端。以下是单实例配置示例，证书路径、域名、网络访问范围和超时需按部署环境填写。

## Nginx 示例

```nginx
upstream auto_router {
    server 127.0.0.1:8787;
    keepalive 32;
}

server {
    listen 443 ssl;
    server_name router.example.com;
    ssl_certificate /etc/nginx/certs/router.crt;
    ssl_certificate_key /etc/nginx/certs/router.key;

    location / {
        proxy_pass http://auto_router;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_connect_timeout 5s;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }

    location = /metrics {
        allow 127.0.0.1;
        # 按实际监控来源增加 allow，仍需携带 METRICS_TOKEN。
        deny all;
        proxy_pass http://auto_router;
    }
}
```

示例中的 600 秒是代理超时，不能覆盖客户端、路由器或上游自己的超时。不要在代理层把调用方 `Authorization` 替换成统一服务 key，否则会改变租户归属。管理页面和 API 的访问范围按组织要求限制，服务端登录鉴权仍保留。

配置完成后先检查语法，再重新加载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

只在语法检查成功后执行重新加载。通过反代地址验证普通请求和 SSE，确认流式片段能及时到达并正常结束。

## Caddy 示例

```caddyfile
router.example.com {
    reverse_proxy 127.0.0.1:8787 {
        flush_interval -1
        transport http {
            dial_timeout 5s
            response_header_timeout 600s
        }
    }
}
```

域名解析、证书签发和访问控制需在目标环境配置并验证。跨域响应头最好由一处维护，避免代理与应用重复设置相互冲突的值。

## 扩容前先处理状态

当前部署没有完成多副本状态一致性的生产验收。多个实例仅共享 `router.json`，不能同步会话、并发、健康、费用和配置发布状态；Node 配置目录还需要可写以完成管理端发布。不要通过共享只读配置卷或复制后端地址来代替扩容设计。

服务端口和停止顺序见 [部署说明](Ubuntu生产部署.md)，本次已验证范围见 [生产验收](go-core-production-v0.14.8.md)。
