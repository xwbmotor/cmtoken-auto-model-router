# 开发指南

接手项目时，先读 [README](../README.md)、本文及本次改动涉及的专题文档。协作与发布规则以根目录 [AGENTS.md](../AGENTS.md) 为准，不在这里重复维护。

## 当前基线

代码主分支是 `master`。2026 年 9 月 11 日完成 v0.14.8 Go 原生入口生产切换，正式源码提交为 `90e6e4eb71ff5e323a39caa87e52e1829e77f332`，对应的测试和回滚依据见 [验收记录](go-core-production-v0.14.8.md)。后续文档提交不等于生产镜像更新；动生产前查实际镜像与配置。

当前请求由 Go 处理，Node 保留管理、配置发布、记录、Judge、费用观察和兼容请求处理，Python 提供小模型分类。生产验收范围是 `passthrough`、预算保护关闭。不要把独立 Go 账本实验、旧 M1–M4 计划或 Node 单进程说明当作当前部署合同。

## 从哪里读代码

| 改动内容 | 主要入口 |
|---|---|
| Go 请求、生命周期、转发与后台复核 | `go-core/internal/gateway/` |
| Go 模块与检查入口 | `go-core/README.md`、`go-core/verify.ps1` |
| Node 管理 API 与兼容请求 | `src/server.mjs` |
| 配置校验与 Go 快照 | `src/config.mjs`、`src/go-runtime/`、`src/go-config-publication.mjs` |
| Go 结果与控制面 | `src/go-core-results.mjs`、`src/go-core-admin.mjs` |
| Node 路由实现与对照 | `src/router.mjs`、`tests/` |
| 页面与交互 | `public/` |
| 发布与部署 | `.github/workflows/release-validation.yml`、`go-core/deployment/` |

Node 路由实现仍用于本地运行、兼容及对照测试。修改公共策略时要检查两种实现的字段和行为是否仍一致，不能只改管理页或只改某一侧的判断。

## 维护时要保留的行为

候选先过启用、权限、能力、容量与质量约束，再评分。会话黏性、任务偏好和回退不能绕过候选资格。调用方鉴权和请求错误、客户端取消、供应商故障分别统计，不把单个租户问题变成全局模型故障。

配置从 Node 校验后发布到 Go。保存、导入和校准都要保持发布顺序与失败恢复行为。结果不确定时先对账，不能假定写入磁盘就已生效。旧配置实例有后台复核时需继续保留，不能在 HTTP 请求结束时立即释放。

Go 停止接入后需等待在途与后台结果，在有界时间内完成排空；Node 必须继续接收回传。生产整体停止时先停 Go，再停 Node 与分类器。v0.14.7 在此处发生过实际回滚，相关失败记录保留在验收文档中。

费用观察和预算保护不是同一件事。当前生产由 Node 记录费用，Go 的空观察 WAL 不能用于替换旧费用台账。原始 key、环境文件和生成后的内部鉴权配置不进入提交或测试输出。

## 开发与验证

日常 Node 开发使用 Node.js 24，分类器依赖见 `requirements-classifier.lock`。Go 模块声明 Go 1.25+，实际 CI 工具版本以工作流为准。

```bash
npm test
```

Windows 的 Go 综合检查：

```powershell
./go-core/verify.ps1
```

测试结果按环境解释。浏览器或分类器依赖缺失造成的跳过不能计作完整发布通过。正式发布需干净且精确匹配标签的工作区、三个同提交镜像以及 `npm run test:release`；使用标签发布工作流可复现构建和归档。

编写进程级测试时注意：

- Windows 的 `child.kill('SIGTERM')` 不能证明 POSIX 优雅关停。Node 本地测试可使用已有 IPC 钩子，Linux CI 仍须验证真实信号；Go 已有真实 SIGTERM 与旧版本失败对照。
- 从合法配置克隆测试数据，只覆盖场景需要的字段。将配置、日志、统计和上游全部指向独立临时位置，尤其核对 `decisionLog.dirPath` 和 `UPSTREAM_BASE_URL`。
- 等待子进程退出和服务端口关闭后再删除目录，避免后台写入与清理竞争。
- 断言最终响应、记录和状态，不能只断言内部函数被调用；SSE 应覆盖结束、断流和取消。
- 运行脚本前检查是否会调用真实模型、读取生产凭证或写入共享数据。正式性能和质量结论需要原始记录，模拟结果应注明来源。

## 文档与历史

[文档目录](README.md)区分当前指南和阶段性证据。CHANGELOG 按版本说明变化，代码注释解释当前实现原因；不再用“第几审”代替问题描述。旧版说明可以在 Git 历史中追溯，不必把全部调试过程堆在交接入口。

仍需真实业务数据验证的部分包括质量分来源补齐、受控业务对照和学习策略收益。多实例共享会话、并发、健康与费用状态也未作为当前生产能力验收。后续工作根据具体目标安排，不把历史待办自动当作本次修改范围。
