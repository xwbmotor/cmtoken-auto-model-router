## 已完成的代码整改

| 项目 | 结果 |
| --- | --- |
| 独立分析入口 | 增加专用进程 `/v1/decide`，独立Token、固定候选交集、输入大小/类型/数量校验、速率并发限制、可取消超时计算。 |
| 分析与转发隔离 | 分析进程不启动模型调用、Judge、后台探测或原文存储，不进入生产outbox/receipts链路；另提供只读、无业务数据挂载的部署模板。 |
| 默认日志脱敏 | 不再保存消息前160字，去掉自由错误回显和可能携带原文的解释；保留任务特征、候选评分、质量分数、用量、费用和结果。 |
| 历史查询与标注 | 默认不返回历史正文和回答；授权全文导出仍可用，凭据始终过滤。明确标记文本是否可用，避免空样本被当成完整训练输入。 |
| 管理鉴权 | 缺少管理凭据时拒绝管理API；native前置代理模式缺少管理凭据时拒绝启动。 |
| 日志完整性 | 修复Linux同毫秒轮转文件名冲突造成的覆盖，固定时间连续轮转测试确认记录不丢失。 |

日志和管理鉴权修复已在生产0.14.12生效。独立分析入口随镜像提供，尚未自动接入中台生产请求，其部署与数据范围按工程配合清单落实。

## 数据飞轮与工程配合

本次没有删除训练、Judge、反馈、样本采集或正常转发对账能力，也没有自动开启额外采集。纯分析进程与正常网关采用不同的数据处理范围。

新分析入口目前仅做规则计算，默认单条user文本，批准后可开启有界文本历史；不把它当成完整语义、多模态路由效果的复现。真实执行模型、usage、成本、时延和质量反馈由中台关联；语义分类器训练与案例重放仍需要获批文本样本。

推荐在中台受控域保留获批样本和业务映射，分析虚拟机只处理输入并返回结构化结果。全面禁文本、禁回答及质量评估、禁事件关联、过度裁剪上下文、过滤偏差、禁多候选评估和过短保留期限的影响及替代方案，已逐项列入[工程配合与数据飞轮清单](security-analysis-integration.md)。实际采样范围、期限及评估调用仍需业务与安全方确定。

启动参数、接口边界和审计交付要求见[独立分析服务说明](analysis-service.md)。
