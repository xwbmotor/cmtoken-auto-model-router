## 生产请求

更新及 Go 重启后分别完成一次 JSON 和一次 SSE 请求，共 4 次，均返回 200 且完整交付。对应决策记录各一条，四条语义复核均完成。

| 阶段 | 类型 | 完整请求耗时 |
|---|---|---:|
| 更新后 | JSON | 0.812 秒 |
| 更新后 | SSE | 0.872 秒 |
| Go 重启后 | JSON | 0.927 秒 |
| Go 重启后 | SSE | 0.673 秒 |

验收结束时待回传数量为 0、待核对记录为 0，配置同步正常，评测 API 已报告支持重启保留。以上是功能验收样本，不能据此估计生产 P95。

首次更新通过了真实请求和记录检查，但重启后的最后检查早于 Docker 首次健康探针，误将 `starting` 判为失败并回滚。事件记录显示 Go 重启后 3 秒即触发检查，而探针在第 5 秒运行。部署脚本改为等待实际健康状态，并用新请求 ID 重新验收；应用镜像和标签没有改变。首次与第二次记录均保留。

## 容量对照

[两轮隔离实验](https://github.com/xwbmotor/cmtoken-auto-model-router/actions/runs/34857150062)使用每组 2 CPU、512 MiB，关闭 Judge、语义复核和限流，调用模拟上游。每轮 Node 和 Go 均完成全部 12,036 个请求，决策记录无缺失、无重复；没有请求错误或发压丢弃。32 路、每路 60 秒的 SSE 检查通过。

| 目标负载 | Node P95，两轮 | Go P95，两轮 |
|---|---|---|
| 100 RPS | 15.82 / 15.80 ms | 19.13 / 19.16 ms |
| 300 RPS | 26.20 / 26.09 ms | 38.44 / 35.58 ms |

新路径增加耐久回传，在该实验中存在处理开销，不宣称所有场景都比 Node 更快。不同实现之间的差值包含语言、进程和持久化方式等因素，不能全部归因给某一个写盘操作。

性能实验对应 `722e130`；它与正式标签之间的服务端、前端及 Go 运行时代码相同，后续提交涉及测试和安装工具。初版逐条同步、串行回传曾出现显著延迟及请求失败，未部署；批量确认和移除共享磁盘锁后通过复验。容量工作流已加入错误、丢弃、完整交付及日志一致性检查，采集完成不再自动等同于通过。
