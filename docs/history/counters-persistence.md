# 累计请求统计的持久化记录

本页记录 v0.11.14 开发期间发现的问题及后续修复。当前安装与运维步骤见 [部署说明](../Ubuntu生产部署.md)，本页不是待执行的发布任务。

## 统计如何保存

累计请求数由 Node 保存到 JSON 文件，启动时恢复。路径由 `AMR_COUNTERS_PATH` 指定，未设置时使用 `data/counters.json`。当时增加了合并写入，避免每次计数都单独写盘。

v0.11.16 随后补充串行写入、关闭前最终快照、启动前等待恢复、结构校验和首次启动时间持久化。具体变化见 [版本记录](../../CHANGELOG.md)。

## 测试隔离

持久化上线后，进程级测试如果共用默认统计路径，就会读到前一个测试的累计值，造成单独运行成功、整套运行失败。

创建测试服务时，应同时指定独立的配置、日志、费用和统计路径。`AMR_COUNTERS_PATH` 指向该测试的临时目录，结束时等待子进程退出再清理。累计统计的回归测试见 `tests/itl-counters-persist.test.mjs`。

## 排查经验

- 文件系统方法需显式导入，保存失败要有可观察的错误，不能用空的异常处理隐藏。
- 生成或修改脚本后先检查语法，再运行涉及写盘和重启的场景。
- 构建前确认 Docker 服务可用；构建失败与应用测试失败分别定位。

早期临时脚本、当时未完成的方案和评审等待状态不再作为当前操作指引。完整修改过程可在 Git 历史中追溯。
