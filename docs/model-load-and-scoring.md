# 模型评分与并发调度（v0.14.1）

业务策略页使用 12 个固定样例做静态模拟，不含实时健康、并发、租户权益和会话黏性。模型未出现时先检查各行的“未进入候选”，不能据此认定模型能力不足。质量分仍为配置中的历史评测或人工先验；本次不重写分数，也不把功能探测当作业务质量重测。

## 思考预算

`minimumCompletionTokensForReliableAnswer` 保留为思考预留。低于该预留的请求，只有已经验证的 `chat_template_kwargs.enable_thinking=false`（客户端显式设置，或开启路由思考控制且当前建议 off）可以免除此门槛。启用思考或无法证明思考已关闭时，仍拒绝低预算候选。自动路由和显式点名使用同一判断。不会为了让模型参与分流而擅自关闭复杂任务的思考；客户端明确参数也不被覆盖。

## 本进程并发

每次模型调用在第一个异步等待前原子占用额度；完整交付、上游失败、客户端断开均释放，释放操作幂等。指标 `router_model_inflight{model="..."}` 始终记录本路由进程的在途调用。管理页同步显示，决策日志保存候选负载快照。

可通过配置显式开启负载策略：

```json
{"routing":{"loadBalancing":{"enabled":true,"penaltyWeight":0.2,"limits":{"example-model":10}}}}
```

`example-model` 必须换为已存在的模型；10 仅为语法示例，不是生产建议额度。`limits` 是分配给本路由进程的最大并发调用数，不能直接复制全模型池容量。缺失额度只观测、不惩罚、不限流；未配置或 enabled=false 时亦只观测。

在满足能力及质量门槛的候选中，扣分为 `penaltyWeight × min(1, 在途数/额度)²`。已满额候选不参与选择；会话黏性不能绕过，执行前还会再次原子检查，防止多个请求同时选到同一剩余额度。合格候选均满额时返回 503，不降低质量门槛承接，也不计为模型健康失败。本层没有排队系统，不会无限等待。

仅覆盖本进程经业务代理发出的调用；其他路由副本、上游直接调用、管理评测及外部服务的占用不在此计数内。多副本或共享 MaaS 池需先划分每副本额度，或接入真实共享容量数据。现有 deployment.totalConcurrency 仍是登记容量，不会自动变成独占额度。

## 评分复核状态

- 已复算：线上平台资源成本项是 Qwen3.6 大量获选的主要原因之一。
- 已发现：30 个小类中，每模型只有 4 类达到 n>=4，其余回落到大类分；quality.simple 不对应当前 analysis.task。
- 已追溯：Qwen3.6 default 的 0.894 标注为剔除 default-06 歧义题后的人工修订；Qwen3.8 coding 的 0.930 标注为历史质量 0.940 乘可用性折让。它们不等于同一新评测的原始均值。
- 已确认（2026-09-07）：设备数为全池合计，TPS 为单实例输出；全池资源强度改为总设备×单机卡数×卡型权重÷（实例数×单实例输出 TPS）。按现有 12/4/20 实例，平台指数为 DS4 Flash 1.000、Qwen3.6 0.396、Qwen3.8 0.687。这里是按实例数线性估算的相对资源强度，不是新的全池压测结果。
- 待完成：统一题集、思考模式、输出预算、失败统计及 Judge 标准的业务质量重测。本次 3 个小任务的开关探测仅验证协议行为，不足以更新质量分或验证生产收益。

## 当前生产额度

用户确认全池并发均可由本路由器使用，且当前云端只有一个业务路由进程。v0.14.1 启用 `loadBalancing`，额度分别为 DS4 Flash 180、Qwen3.6 180、Qwen3.8 300，惩罚权重 0.2。未来增加路由副本时必须分配额度或改为共享计数，不能让每个副本重复拥有全部容量。定价、质量分和原有评分权重未修改。
