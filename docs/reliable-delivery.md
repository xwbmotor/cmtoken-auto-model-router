# 结果回传与评测任务恢复

Go 请求完成后，将结果加密保存到 `runtime.wal.outbox/`，后台批量回传给 Node。每批最多 16 条，确认前完成持久化；批处理不改变逐事件去重规则。只有 Node 确认处理并保存后才删除待发送记录；重启后会继续发送，不重新调用上游模型。队列最多 4096 条、256 MiB，存储不可用或达到上限时拒绝新的原生请求。

Node 在 `data/native-receipts/receipts.sqlite` 中保存接收状态，以事件 ID 和内容摘要去重。重复确认不会再次计费或启动 Judge。待核对的事件内容加密保存，完成后清除正文；配置快照也加密保存，供延迟结果核对使用。密钥文件必须与对应数据一起保留，不得单独删除或重新生成。

## 正常恢复

本机制覆盖 Go 原生完成事件和语义复核事件。Node 兼容入口仍沿用原同步处理方式。

Node 短暂不可用时，Go 保留待发送记录，Node 恢复后自动补发。业务时延使用原请求结束时间，不把等待回传的时间当成模型响应时延。管理端 Go 状态显示待回传数量。

整体停止仍须先停 Go，再停 Node 和分类器，让结果有机会完成回传。若停止超时，保留待发送目录和接收数据库，恢复后继续核对。回滚旧版本之前须确认队列已清空；旧版本不具备新接收记录的去重能力。

## 处理中断后的核对

如果 Node 在“开始处理”和“确认完成”之间异常退出，无法仅凭重试判断费用和日志是否已部分写入。此时保留加密记录，并暂停新请求，不自动重做可能已经发生的结算。管理端会显示需要核对。

先在 Node 容器中查看记录 ID 和摘要：

```bash
docker compose -f compose.json exec auto-model-router \
  node src/reconcile-native.mjs inspect --dir /app/data/native-receipts
```

按实际部署替换 Compose 文件路径及项目名。随后先停止 Go，再停止 Node，保存数据备份，并根据请求 ID 核对费用台账和决策记录。

- 已确认费用及必要记录都已写入：使用 `mark-applied` 标记完成。
- 已确认没有任何处理效果：使用 `retry-unapplied`，让 Go 在恢复后补发。
- 只有部分效果或无法确定：保持暂停，先核对并修复记录，不能猜测选择其中一项。

修改命令只用于停止服务后的人工核对，必须提供 `--id`、`--digest`、`--confirm-offline` 和正确目录。工具会先保留加密备份，再修改接收状态，不调用模型，也不自动调整费用。可使用同版本 Node 镜像挂载该实例的数据目录运行 `src/reconcile-native.mjs`。处理后重启服务，让队列完成确认，再检查健康和费用记录。

待发送事件超过 24 小时不会自动应用，应按同样方式核对；已完成的去重记录保留至少 26 小时。接收存储有容量限制，需监控磁盘和队列，不能把待发送文件当作普通缓存删除。

## 评测任务

评测任务在开始执行前保存，每个生成结果和 Judge 步骤完成后保存进度。默认保存在 `data/eval-jobs.json`，可用 `AMR_EVAL_JOBS_PATH` 指定；自定义 `CONFIG_PATH` 且未指定任务路径时，文件位于该配置旁。

重启后保留完成结果，将未完成任务标记为“已中断”，不自动重新调用模型。需要重新评测时由管理员发起新任务。已结束记录最多保留两小时、32 条，总文件限制为 32 MiB，文件权限为 600。评测内容可能包含题目和回答，按业务数据保管。
