## 性能对照怎样避免误判

先把目标写成：请求/秒、同时在线 SSE 数、请求和响应体分布、允许的网关附加 P95/P99 延迟、CPU/内存配额、错误率和完整交付率。

至少分别测三组：

1. 同一特征输入的纯选模内核，明确排除分类、序列化和网络的范围。
2. 可控模拟上游的完整网关链路，包含输入解析、连接、转发和持续流量下的排队；同时测短请求与长 SSE。
3. 代表真实任务的完整链路，保持模型与策略一致，分开统计网关开销、分类复核、上游排队与模型推理。

正式比较不把带 Node 适配器的 Go 实验链路当成最终 Go 架构，也不能拿 Go 的纯内核时间与 Node 的整条请求时间比较。单次突发排空、功能测试通过、或 Go 原生并发支持都不能证明线上容量优势。

## 分支交付和发布边界

- M1 可以提交并推送迁移分支，CI 只运行本地模拟与离线检查，不部署。
- 当前不修改 package 版本、生产 Compose 或线上配置，不创建伪装成正式版本的发布标签。
- 合并现有 Node 改动时重跑差分语料；允许扩大语料，不通过放宽关键结果比较来掩盖差异。
- 达到生产候选阶段后，再沿用项目正式版本、镜像 revision、发布测试、备份和线上验收要求。
