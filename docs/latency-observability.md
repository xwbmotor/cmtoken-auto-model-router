# 模型时延观测与影子评分

v0.14.2 在“效果洞察”新增模型时延观测。真实代理调用结束时采集，失败回退的每次尝试单独留痕；没有新增旁路复制用户请求。历史质量、定价、成本指数和当前选模策略不因这次观测上线而改变。

## 计时与样本

- 首个正文：从业务请求进入路由器到首个非空正文 SSE 事件，包含此前路由与回退等待。
- 首个输出：同一起点，到正文、思考或工具调用的首次有效输出；角色、心跳、usage 和 DONE 不算输出。
- 完整交付：从业务请求进入到最终交付结束。长输出、思考、路由和回退均会影响该值。
- 上游尝试：从本次上游调用开始到交付结束，不把前一次失败的耗时算给下一模型。上游内部排队、网络与生成无法仅凭这个值拆分。
- 非流式不生成虚构 TTFT；工具纯输出不生成虚构正文 TTFT。分位数只纳入成功样本，失败、超时和客户端取消另列，快速错误不会形成“模型很快”的证据。
- 补测是独立来源：固定短算术请求、流式、最多 128 输出 token、20 秒总超时。协议完成与有正文不等于完整业务质量验证，不能据此更新质量评分。

近期窗口以分钟桶近似最近 5/30 分钟，边界误差小于一分钟。热力图按北京时间 24 小时聚合近 14 天的直方图；周一至五/周六日仅是星期分类，不识别法定节假日或调休。今日卡片不随热力图星期筛选改变。

P50/P95 是直方图桶上界近似值，合并原始桶计数后再算分位数，不平均各时段 P95。P95 至少需要 40 个有效样本才显示，这只是展示下限，不等于统计精度保证。每个格子同时提供有效计时数、总次数、成功、失败、取消和最近更新时间。

页面可按来源、流式、思考开关、输入长度和输出预算筛选。输入短/中/长为估算输入 token ≤1024、≤8192、>8192；输出按请求预算 ≤256、≤2048、>2048 分组，不是实际生成长度。页面总览跨上游/凭据及具体推理配置汇总，只用于观察；影子评分使用下述严格分组。

## 影子评分

严格按模型、上游与凭据的不可逆指纹、有效推理配置、流式、输入长度及输出预算分组；补测样本不进入业务排名。流式关思考看本次尝试首正文，开思考看首输出，非流式看本次完成耗时。任务类型、是否请求工具和生成参数也参与严格分组；工具请求使用首输出，当前结果只作影子证据。

默认至少 20 个有效样本、近 30 分钟成功比例不低于 90%、该指标最后样本不超过 5 分钟；样本不足/过期时不调整。调整按样本与新鲜度缩小，幅度最多 ±0.05，候选切换需达到 0.02 分差。新项试算替换原有静态时延与动态时延部分，保留错误、质量、成本与负载项，避免重复扣分。

`routing.latencyObservation.mode` 只支持 `off` 与 `shadow`。影子排名限定在当前质量与容量合格池，保留任务偏好，但发生在会话黏性处理之前，不等于最终模型切换预测。记录 `decision.latencyShadow` 与候选 `latencyEvidence`；不改实际选择、回退顺序或质量门槛。未经同类请求对照验证，不开放自动采纳或宣称生产收益。

## 补测、费用与运行

生产计划每 5 分钟检查一次，只选一个最久未测的启用模型；同模型默认至少间隔 15 分钟，手动补测也受单任务互斥、至少一分钟间隔和每日 144 次额度约束。每天按北京时间切换预算，先将预占额度落盘再发请求；异常/未知调用不退次数，预算文件损坏或持久化失败时暂停补测。所有补测使用服务端已有凭据，不借用业务调用方凭据。

业务占用达到分配额度的 80% 时跳过，补测本身也占用本进程额度。未配置上游/服务端凭据、低输出预算与模型思考要求不兼容时跳过。自动补测在仓库默认配置中关闭；生产部署仅按本次批准迁移开启。`POST /admin/api/latency/probe` 为经管理鉴权的手动操作，不接受任意目标 URL 或请求内容。

补测实际费用与无 usage 的估算费用独立计入 `probeActualCostYuan`/`probeEstimatedCostYuan`，仍纳入总支出和预算压力，不混入业务回答成本。调用次数额度包含保守预占和跳过次数，可能高于实际发出的上游调用数。最坏输出预算为 144×128 token/天，输入另计；实际金额以费用分项为准。

分钟与小时两层各最多 24,000 个桶，超过上限提前淘汰并显示提示，不承诺任意流量下完整保留 14 天。默认写入 `data/latency-observations.json`，30 秒合并持久化、停机最终写入；非正常退出可能丢失尚未保存的近期观测，补测调用额度另有调用前持久化保障。历史 v2 日志没有足够严格分组信息，本版不强行回填成新口径样本。

## 验收和下一步

单元/真实代理/浏览器检查覆盖分组隔离、失败与取消、时区、分位数、预算重启、存储损坏、质量/容量门槛与影子不改变真实选择。上线还应核对双服务、静态资源、鉴权、真实非流式/SSE、一次补测及费用分项。

先积累可比较样本，再决定是否增加任务/工具分组、上游队列指标和小比例在线对照。功能、运营、算法及布局的具体建议见 [标杆对照路线图](benchmark-roadmap.md)。每周定时任务仅做只读复盘与建议，不自动修改、付费探测、推送或部署。


## v0.14.3 运营与解释

- 证据覆盖率按实际 Auto 请求进入影子评估时的合格且未满额候选统计；请求分母与候选原因次数分开。最近30分钟按分钟桶近似，且仅保留本进程启动后的评估；重启重新积累并展示起点。不随热力图筛选改变，不代表影子收益，也不从跨条件热力图反推可用性。
- 自动补测以最后一次预留时间、当天剩余次数和距 UTC+8 午夜的时间计算间隔，避免定时任务提前耗尽全天额度；每5分钟检查，因此实际频次可能低于额度上限。手动请求可绕过预算节奏和模型间隔，仍需一分钟冷却、串行和每日硬上限。所有预留先落盘，失败和跳过不退次数。
- 同上游及服务端凭据作用域内，最近完整5分钟桶至少20条成功的业务首输出计时，且成功占成功与失败总数至少90%，则跳过自动可用性补测；不同凭据和补测样本不混用。这里只减少可用性补测，不把跨任务输出混合数据用于路由排名。失败/跳过继续等待模型间隔，未增加付费调用上限。
- 调度状态标明最早允许时间、5分钟检查周期、最近决策和各模型等待原因；不把允许时间当作确定执行时间。
- 模型主表默认隐藏参数列，详情面板保留原有草稿机制，关闭不发布；完整参数列仍可展开。详情展示30分钟业务首正文P50及有效样本、失败、取消，不将非流式完整响应冒充首字。
- 调试页面显示资格过滤、质量门槛、成本、负载、时延证据和影子变化，保留原分类明细。预演不携带历史会话，也不代表真实请求已执行。
- 近期调用方为当前最近请求列表去重；健康EWMA含成功/失败，累计失败不代表当前窗口故障。
